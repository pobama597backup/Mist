# ADR 0003 — Gateway-aware CSP, cookies, and the Origin===Host voucher

- **Problem**: Phase 1's `frame-ancestors 'none'` (commit 03995d4) made the browser refuse to render her inside the platform preview panel (a cross-site iframe) — "she is not opening in the preview" — while the `SameSite=Strict` auto-pair cookie is never replayed from a cross-site iframe, so every non-GET `/api/mist` call would 403 even once framed; browsers that block third-party cookies outright (Safari/ITP, Chrome 3PC) and headless test browsers that omit fetch-metadata (HeadlessChrome/153 sends Origin but no Sec-Fetch-Site) die on both layers.
- **Decision**: Detect gateway mode as "request Host is non-loopback" (Caddy preserves the external Host, per ADR-0002). In gateway mode: (1) CSP omits `frame-ancestors` entirely — the platform parent origin is unknowable from inside; (2) the auto-pair cookie becomes `SameSite=None; Secure` (the browser-side platform connection is https, even though x-forwarded-proto arrives http from the internal Caddy hop); (3) the non-GET session gate and the neural socket door accept **Origin===Host** as the owner voucher. Loopback (PC/direct) keeps the strict posture unchanged.
- **Why Origin===Host is safe**: layer 2 has already rejected every Origin-mismatched non-GET request, and browsers always attach the true Origin to cross-origin requests — a third-party page can never present this shape; it is exactly the app's own document, including inside the preview iframe. The auto-pair cookie was never an auth boundary (any GET mints one); it is a CSRF boundary, and the voucher preserves that.
- **Consequence**: The preview panel renders her and the app is fully commandable inside it (verified end-to-end: page render + neural link online + chat round-trip + cross-site iframe embed, zero console errors); the CSRF class stays blocked (foreign-Origin POST → 403, foreign-Origin socket → refused — 64/64 security tests green). Honest limits: gateway-mode framing is unrestricted (unknowable parent), and mic use inside an iframe still depends on the platform's `allow="microphone"` (use "Open in New Tab" for voice); dev-server OOM kills (2.1-2.4GB RSS on the 4GB box under browser+tests) now self-heal ≤90s via the hardened dev-guard.
- **Revisit**: Phase 2's Arbiter becomes the real authority boundary for actuators; consider a session-token header lane (Authorization) if the platform ever blocks cookies AND mangles Origin.
