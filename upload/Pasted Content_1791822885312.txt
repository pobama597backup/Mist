━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The work is successful only when:

- Existing credentials and settings remain intact.
- Provider routing remains truthful and functional.
- Threads load correctly.
- New threads can be created.
- Conversations remain associated with the correct threads.
- The intended assistant personality is preserved across supported routes.
- Voice input and actual audible voice output work in the tested environment.
- Playback failures provide useful recovery actions.
- Interruptions stop stale speech.
- The orb reflects real assistant states.
- The orb is correctly positioned at tested screen sizes.
- Orb animations feel intentional, smooth, and distinct across supported states.
- Selecting a thread closes overlay navigation correctly.
- Thread navigation does not unexpectedly take over the entire chat experience.
- Notifications support useful actions.
- Notifications can be dismissed through touch, pointer, and keyboard-accessible alternatives.
- Notifications can open relevant conversations or tasks.
- Dismissing a notification does not falsely resolve its underlying issue.
- Toasts do not obstruct important controls.
- All major UI elements share a coherent design language.
- Buttons, inputs, menus, dialogs, cards, panels, tabs, notifications, forms, and controls have appropriate interaction states.
- Loading, empty, success, warning, error, disabled, hover, focus, pressed, selected, active, and dragged states are clear where relevant.
- Reduced-motion behavior works.
- Responsive behavior works across compact, medium, and wide layouts.
- The application does not expose or overwrite secrets.
- No relevant build, type, test, or runtime regressions are introduced.
- User data is preserved.
- The final interface looks intentionally designed rather than merely patched.
- Every concern from the original user feedback has been explicitly considered and verified where possible.

Add or update automated tests for important regressions. Use manual end-to-end verification for interactions that cannot be reliably automated.

If a test depends on unavailable credentials, hardware, browser permissions, or provider access, mark it blocked or unverified. Never report it as passed.

1. Confirmed root causes.
2. Main functional fixes.
3. Main UI and design-system changes.
4. Screens and components redesigned.
5. Research sources and the decisions they influenced.
6. Tests performed and results.
7. Passed, failed, blocked, and unverified items.
8. Any remaining limitations or setup requirements.
9. Before-and-after screenshots or visual evidence where available.

Explicitly confirm that you considered:

- Orb placement.
- Orb state animations.
- Idle, listening, thinking, speaking, and dreaming behavior where supported.
- Notification actions.
- Notification dismissal.
- Swipe-to-dismiss.
- Notification popup positioning.
- Chat layout.
- Thread placement.
- Thread-panel closing behavior.
- API-key persistence.
- Thread loading.
- New-thread creation.
- Voice output.
- Browser audio playback.
- Assistant personality.
- Full UI-element redesign.
- Responsive behavior.
- Accessibility.
- Motion preferences.
- Regression safety.

Do not claim that everything is production-ready or fully fixed without verification.

Begin by inspecting the existing project and rendered interface. Continue from the current state, preserve the work already completed, and carry the improvements through implementation and verification.
